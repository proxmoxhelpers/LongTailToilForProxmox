## Failing cases

### `rename-lvm.sh`

The log stopped after:

```text
[OK] Elevation: running as root.
```

Root cause:

```sh
lvs "$VG_NAME/$NEW_NAME" >/dev/null 2>&1 && die "Destination logical volume already exists..."
```

The destination correctly did not exist. `lvs` therefore returned 1. Because the AND-list was the final command of `validate_rename()`, the function returned 1 and `set -e` terminated the script.

### `renumber-vm-disks.sh`

The log also stopped immediately after elevation.

Root cause:

```sh
grep -qE '^\[[^]]+\]$' "$CONFIG" && die "VM snapshots/config sections detected..."
```

No snapshot section is the successful state, but `grep` returned 1 and the function returned that status to `set -e`.

A second latent instance existed in temporary-LV collision validation.

### `recover-vm-from-volumes.sh`

The log stopped after elevation.

Root cause:

```sh
find ... | grep -q . && die "VMID already exists"
```

An unused VMID is the desired condition. The negative lookup returned 1, which became the function status and triggered `set -e`.

### `unmount-vm-drives.sh`

The script actually:

```text
found the mounted filesystem
successfully unmounted it
removed the empty part1 directory
```

It then failed during the absence-verification phase because:

```sh
findmnt ... && die "still mounted"
```

returned 1 when the filesystem was correctly absent. That 1 became the function return status.

### `mount-vm-disk.sh`

The real mount itself succeeded and the filesystem was verified. Its test case failed later when the cleanup call to the affected `unmount-vm-drives.sh` returned 1 after successful unmount.

### `mount-vm-root.sh`

The real mount and Linux-root detection succeeded. The captured output included:

```text
Linux root
```

Its test case likewise failed only when cleanup called the affected `unmount-vm-drives.sh`.

## Additional latent regression found during review

`set-vm-boot-disk.sh` had a related construct inside the boot-order loop:

```sh
[ -n "$item" ] && [ "$item" != "$SLOT" ] && NEW="..."
```

The current fixture passed, but a normal false condition in the last loop iteration could become the function return status under `set -e`.

v3.0.1 changes this to explicit `if` control flow.

## v3.0.1 correction strategy

The patch:

```text
replaces project `&& die` negative probes with explicit if blocks
adds explicit return 0 to corrected validators
hardens boot-order loop control
adds a static regression forbidding `&& die`
keeps the existing real-system test matrix unchanged
```

The correct retest sequence is:

```sh
./tests/groups/20-lvm.sh --run --verbose
./tests/groups/30-mount.sh --run --verbose
./tests/groups/60-disk-config.sh --run --verbose
./tests/groups/80-vm-config.sh --run --verbose
```

If those pass, run the complete suite again:

```sh
./tests/run-all-tests.sh --run --verbose
```

v3.0.1 should not be promoted to the new integration-validated baseline until the complete run finishes with all groups green and zero protected-state anomalies.
