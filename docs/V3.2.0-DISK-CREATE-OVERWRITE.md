# v3.2.0 Disk Create / Overwrite Helpers

Version 3.2.0 adds two overwrite helpers and expands both existing create-and-add helpers.

## Source syntax

All four helpers accept either:

```sh
/dev/pve/vm-123-disk-0
```

or:

```sh
123 disk-0
```

Plain numeric backing selectors such as `0` are also accepted, as are explicit QEMU slots such as `scsi0`.

## Existing create-and-add helpers

### `create-disk-copy-and-add-to-vm.sh`

Examples:

```sh
./create-disk-copy-and-add-to-vm.sh /dev/pve/vm-123-disk-0 456 dryrun
./create-disk-copy-and-add-to-vm.sh 123 disk-0 456 disk-3 pause dryrun
./create-disk-copy-and-add-to-vm.sh 123 disk-0 456 disk-3 fastvg restart dryrun
```

The optional destination disk selector controls the new backing name `vm-DESTVMID-disk-N`. The copy helper still accepts the previous positional destination-VG form when that positional value is nonnumeric.

### `create-disk-snapshot-and-add-to-vm.sh`

Examples:

```sh
./create-disk-snapshot-and-add-to-vm.sh /dev/pve/vm-123-disk-0 456 dryrun
./create-disk-snapshot-and-add-to-vm.sh 123 disk-0 456 disk-3 pause dryrun
```

The optional destination disk selector controls the new snapshot backing name.

For both create-and-add helpers, `pause`, `stop`, and `restart` apply to the **source VM** so the source can be held stable while the copy/snapshot is created. Hot mode is the default.

## New overwrite helpers

### `create-disk-copy-and-overwrite-disk-on-vm.sh`

Accepted destination forms:

```sh
456 disk-1
```

or:

```sh
/dev/pve/vm-456-disk-1
```

Examples:

```sh
./create-disk-copy-and-overwrite-disk-on-vm.sh /dev/pve/vm-123-disk-0 456 disk-1 dryrun
./create-disk-copy-and-overwrite-disk-on-vm.sh 123 disk-0 456 disk-1 pause dryrun
./create-disk-copy-and-overwrite-disk-on-vm.sh /dev/pve/vm-123-disk-0 /dev/pve/vm-456-disk-1 restart dryrun
```

The source is copied into the same LVM/LVM-thin backing storage as the destination disk, byte-verified, and then attached at the exact destination slot.

### `create-disk-snapshot-and-overwrite-disk-on-vm.sh`

Examples:

```sh
./create-disk-snapshot-and-overwrite-disk-on-vm.sh /dev/pve/vm-123-disk-0 456 disk-1 dryrun
./create-disk-snapshot-and-overwrite-disk-on-vm.sh 123 disk-0 456 disk-1 pause dryrun
./create-disk-snapshot-and-overwrite-disk-on-vm.sh /dev/pve/vm-123-disk-0 /dev/pve/vm-456-disk-1 restart dryrun
```

The snapshot remains in the source thin pool and replaces the destination slot by Proxmox volume ID.

## Overwrite safety model

Overwrite means **replace the VM slot**, not destroy the previous LV contents.

The transaction is:

```text
preflight source and destination
create/verify copy or snapshot
apply requested destination VM state
detach old destination disk
verify old disk was preserved as unusedN
attach replacement at exact original slot/options
restore destination VM state when pause/restart was requested
verify new slot + preserved old volume
```

If replacement attachment fails before the new volume is referenced, the helper attempts to restore the exact original destination slot/value. An unattached replacement LV/snapshot is removed only when no guest configuration references it.

The old destination volume is intentionally retained as `unusedN`.

## State keywords

The keywords can appear anywhere on the command line.

For overwrite helpers:

```text
default   hot replacement; destination VM state unchanged
pause     pause running destination VM, replace disk, resume
stop      stop destination VM, replace disk, leave stopped
restart   stop destination VM, replace disk, start it again
```

A destination VM that was already stopped is not started merely because `restart` was specified.

For create-and-add helpers the same keywords apply to the **source VM**.

## Copy consistency

A full block copy from a running source VM can only be as application-consistent as the source workload allows. Use `pause`, `stop`, guest quiescing, or an application-aware method when crash consistency is insufficient.

LVM-thin snapshots provide a point-in-time block snapshot, but guest/application consistency still depends on what the guest was doing at snapshot creation.
