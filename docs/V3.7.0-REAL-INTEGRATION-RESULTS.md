## Failed cases and corrective action

### Test-only: unmanaged-name fixture

`fix-vm-volume-names.sh leaves unmanaged LVM names unchanged` failed while preparing the fixture:

```text
unable to parse lvm volume name 'custom-<VMID>-root'
```

Proxmox LVM-thin rejected the arbitrary name before the helper ran. v3.7.1 uses a valid managed configured disk plus an unrelated custom LV in the owned VG and proves the custom LV UUID/name is untouched.

### Product: disk-option canonical ordering

`copy-vm-disk-options.sh` applied the requested options correctly, but Proxmox reordered the comma-separated fields. v3.7.0 compared the complete string literally and rolled the valid change back.

v3.7.1 preserves exact backing-volume comparison while canonicalizing/sorting option tokens for semantic equality.

### Product: block device passed to `qm importdisk`

Two `clone-vm-storage-only.sh` cases failed because qemu-server 8.4.3 requires a regular import image and rejected `/dev/VG/LV`.

v3.7.1 stages guest-visible source content into an owned regular raw image, imports that file, verifies the imported bytes against the immutable stage, restores temporary source activation and removes staging data on every exit path.

### Test-only: archive checksum working directory

The archive was created successfully, but the test changed into `ltvm/` before validating a checksum file whose members are intentionally prefixed `ltvm/...`.

v3.7.1 validates from the extraction root, matching the embedded restore program.

### Product/policy: regenerated QEMU `vmgenid`

Exact same-VMID restore successfully restored disk content, but Proxmox generated a new `vmgenid`, causing literal config equality to fail.

v3.7.1 treats `vmgenid` as a hypervisor generation marker: it is excluded from persistent-config equality, but a restored QEMU VM is still required to have a generated value when the archived config had one.

### Product: remote dry-run contacted SSH

`send-vm-export-and-restore.sh` performed remote preflight before its dry-run return, causing an SSH host-key prompt and potential `known_hosts` mutation.

v3.7.1 returns from dry-run before any SSH/SCP call. Explicit `--preflight` performs the remote read-only checks and requires an already-trusted host key.
