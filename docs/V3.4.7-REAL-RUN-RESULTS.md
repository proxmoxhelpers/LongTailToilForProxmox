## Failed cases

Both failures were independent-copy operations using a real Proxmox template/base source LV:

```text
create-disk-copy-and-add-to-vm.sh base/template naming
create-disk-copy-and-overwrite-disk-on-vm.sh inactive base source
```

Both stopped at:

```text
Source LV is inactive; temporarily activating it for the block copy...
ERROR: Source LV activation succeeded but no block device appeared: /dev/.../base-...-disk-0
```

No destination-copy/replacement transaction had started at that point. The `50-copy-snapshot` group reported zero protected-state anomalies.

## Network anomaly

All three `bulk-change-vm-network.sh` functional cases passed. Cleanup retained one disposable LXC config because its rootfs storage could not be proven test-owned.

The protected guest diff contains only the additional disposable CT config. The supplied result set shows no protected-state difference in guest runtime, firewall, storage, VG, PV, or LV snapshots.

## Disposition

v3.4.7 is **not** a clean integration-validated release because of the two failed cases and one cleanup anomaly.

The fixes are carried in v3.5.1 and documented in:
