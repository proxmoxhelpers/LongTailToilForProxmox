# v3.2.1 — overwrite disk-number semantics

`create-disk-copy-and-overwrite-disk-on-vm.sh` and `create-disk-snapshot-and-overwrite-disk-on-vm.sh` now retain the destination backing disk number.

If the destination is:

```text
local-lvm:vm-107-disk-1
```

the transaction stages the replacement under a temporary free name, then:

```text
old destination: vm-107-disk-1 -> vm-107-disk-901
replacement:     temporary      -> vm-107-disk-1
```

If `disk-901` already exists, the old disk is moved to `disk-902`, then `disk-903`, and so on until a free number is found.

By default the renamed old volume remains attached to the destination VM as an `unusedN` entry. With the keyword:

```text
delete
```

the helper deletes the archived old LV only after the replacement is attached, verified, and the requested destination VM state has been restored.

The state keywords remain:

```text
hot
pause
stop
restart
```

and both state keywords and `delete` may appear anywhere on the command line.

Examples:

```sh
./create-disk-snapshot-and-overwrite-disk-on-vm.sh 102 disk-23 107 disk-1
```

```sh
./create-disk-snapshot-and-overwrite-disk-on-vm.sh delete 102 disk-23 107 disk-1 restart
```

```sh
./create-disk-copy-and-overwrite-disk-on-vm.sh /dev/thinvg/vm-102-disk-23 /dev/thinvg/vm-107-disk-1 pause
```

The overwrite operation still preserves the destination bus/slot and its disk options. `delete` refers only to the displaced destination disk, never the source or the newly created replacement.
