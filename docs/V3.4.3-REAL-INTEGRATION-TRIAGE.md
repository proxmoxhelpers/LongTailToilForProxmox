Date: 2026-08-17

This patch is based on the first full real-Proxmox attempt of the expanded v3.4.2 / test-suite v2.8.0 definition.

  failed      0

Planned real integration cases:
  total      84

The blocked 30 cases were all in groups whose fixture setup aborted before registered cases began:

## Root causes and corrections

### 1. Invalid `partx --show --raw`

Affected:

```text
10-inspection.sh
30-mount.sh
list-all-vm-lvm-filesystems.sh
```

On util-linux, `--show` and `--raw` are mutually exclusive action/output modes. The real host reported:

```text
partx: mutually exclusive arguments: --pairs --add --delete --list --raw --show --update
```

v3.4.3 uses:

```text
partx --show --noheadings -o ...
```

This remains read-only.

### 2. `move-disk-to-vm.sh` could free the moved LV

This was the most serious defect.

The real transaction successfully detached the source and attached the same LV to the destination. It then attempted to clear the source `unusedN` with:

```text
qm set SOURCE --delete unusedN
```

Proxmox storage semantics freed the backing LV. The subsequent verification correctly failed because the LV no longer existed.

v3.4.3 never clears that source reference through `qm --delete`. It rewrites only the exact `unusedN` config line, verifies that the line is gone, and verifies that the LV still exists. Rollback uses the same config-only path.

### 3. Pause-mode SCSI fixture topology

The pause move failed before the destructive cleanup bug because the disposable VM used `virtio-scsi-single`, and Proxmox attempted to hot-unplug the per-disk controller while the VM was suspended:

```text
hotplug problem - error on hot-unplugging device 'virtioscsi0'
```

The helper correctly attempted rollback and resume.

The positive pause fixture now uses `virtio-scsi-pci`, where the disk is attached behind a shared controller rather than making controller removal part of the test. The script still treats a Proxmox hot-unplug refusal as a safe operation failure rather than forcing config-only detachment of a disk that QEMU may still have open.

### 4. `delete-lvm.sh` cancellation status

The helper printed:

```text
Cancelled.
```

and preserved the LV, but returned status 0. The negative integration test correctly treated that as an automation-semantic failure.

v3.4.3 returns non-zero when the exact `DELETE` token is not entered.

### 5. Undefined `trim` in `50-copy-snapshot.sh`

The group referenced the project-internal `trim` helper 22 times even though the integration test library did not define it. Fixture setup stopped at the first use.

All such test-only calls now use POSIX `awk` whitespace trimming.

### 6. SATA bus validation and `iothread`

The exact bus-change case preserved:

```text
iothread=1
```

when changing a disk from SCSI to SATA. Proxmox rejected the resulting SATA config because `iothread` is not valid for that bus.

v3.4.3 preserves destination-compatible options, removes `iothread` when moving to SATA/IDE, warns about the change, and verifies the sanitized destination value.

### 7. Incorrect omitted-destination test expectation

The fixture had:

```text
scsi0
scsi1
scsi2
scsi3   <- source
```

so the first free SCSI slot was correctly `scsi4`. The test incorrectly asserted `scsi1`.

The assertion now checks `scsi4`.

### 8. Invalid rootless LXC network fixture

The network helper's QEMU paths succeeded, but the synthetic CT had no `rootfs`. `pct set` refused the invalid container configuration with:

```text
missing 'rootfs' configuration
```

The v3.4.3 network fixture creates a disposable test-owned thin LV and configures it as the CT rootfs before exercising `pct set`.

### 9. Brittle qcow2 export assertion

The helper completed the qcow2 export successfully. The integration case then failed in its post-command assertion without a diagnostic message.

v3.4.3 makes the test explicit:

```text
qemu-img info     -> verify qcow2 container format
qemu-img compare  -> verify logical source/export contents
```

Raw export continues to use byte comparison.

### 10. Setup-failure evidence gap

When setup aborted, the emergency trap cleaned up but did not capture protected after-state. v3.4.3 emergency cleanup now runs the same protected-state comparison after cleanup so setup-time failures leave anomaly evidence too.

## New regressions

The static suite now additionally requires:

```text
move-to-VM source unused cleanup is config-only
no partx --show --raw in helpers/integration groups
no integration-group dependency on undefined trim
delete-lvm cancellation exits failure
SATA/IDE bus change sanitizes iothread
emergency cleanup captures protected after-state
```
