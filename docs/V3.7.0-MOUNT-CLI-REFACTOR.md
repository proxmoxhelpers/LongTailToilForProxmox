# v3.7.0 Mount/Unmount and CLI Refactor

## Public command migration

v3.7.0 deliberately changes the public mount/unmount command surface.

| Before v3.7.0 | v3.7.0 replacement | Meaning |
|---|---|---|
| `mount-vm-drives.sh` | `mount-lvm-drives.sh` | Mount recognizable filesystems from one explicitly supplied LVM volume path. |
| `unmount-vm-drives.sh` | `unmount-lvm-drives.sh` | Unmount the selected direct-LVM disk/partition mappings. |
| `mount-vm-disk.sh` | `mount-vm-drive.sh` | Resolve one active QEMU disk slot, mount its filesystems and classify likely filesystem roles. |
| `mount-vm-root.sh` | `mount-vm-drive.sh` | Root-role detection is now part of the normal one-drive VM mount operation. |
| `mount-vm-filesystems.sh` | `mount-all-vm-drives.sh` | Mount and classify recognizable filesystems from every active QEMU disk. |
| `unmount-vm-filesystems.sh` | `unmount-all-vm-drives.sh` | Clean resources recorded by either VM-level mount command. |

The old command files are intentionally not shipped as aliases. This avoids preserving two public names for the same behavior and makes stale automation fail visibly instead of silently acquiring different semantics.

## Layering

The mount family now has two explicit layers.

### Direct LVM layer

`mount-lvm-drives.sh` accepts an LVM block-device path. It does not need a VMID or Proxmox slot. It probes partitioned media through `kpartx`; if a recognizable filesystem is directly on the LV, it is exposed as `part1`. Read-only is the default.

`unmount-lvm-drives.sh` is the matching direct-LVM cleanup helper.

### Proxmox VM layer

`mount-vm-drive.sh` accepts one VMID and one active disk slot.

`mount-all-vm-drives.sh` accepts one VMID and selects all active IDE/SATA/SCSI/VirtIO disk slots.

After slot selection, both commands execute the same implementation. Their source files are required by the static suite to be identical after normalizing the single hard-coded `MOUNT_SCOPE` assignment.

The shared engine:

- requires the QEMU VM to be stopped;
- resolves Proxmox storage references to their backing devices;
- preserves inactive-LV activation state and uses `lvchange -ay -K` when temporary activation is necessary;
- refuses ambiguous pre-existing partition mapper ownership;
- maps partitions through `kpartx`;
- mounts read-only by default, with explicit `--rw` support;
- verifies that every real mount target is backed by the exact canonical source requested;
- classifies recognizable Linux-root, Windows-root, EFI and recovery roles;
- scores Linux-root candidates and reports the strongest candidate;
- records only resources created by the invocation;
- rolls back invocation-owned mounts, mappings, activations and directories if a later step fails.

Both commands write an ownership-state file beneath the mount root. `unmount-all-vm-drives.sh` consumes that file and performs fail-closed cleanup. It verifies recorded mount source/target identity before the first unmount and refuses to clean resources whose current identity no longer matches the record.

## CLI contract

All 81 public commands now implement the same help surface:

```text
-h
-?
/h
/?
--help
```

Help/version handling occurs before the operation/elevation boundary.

When required positional arguments are incomplete, the command prints its usage information and returns a usage error rather than emitting only an unexplained failure.

Each command's live help must:

- identify the command and project version;
- contain a `USAGE` section that lists all supported invocation forms;
- contain a descriptive `DESCRIPTION`;
- mention every long option parsed by the implementation;
- document the common help/version forms;
- document supported dry-run forms where applicable.

The standardized dry-run explanation is exactly:

```text
Dry-run: no system changes are made; modifying commands are printed instead of executed.
```

The static suite compares live `--help`, `.usage` snapshots and the Markdown embedded help block for every current command.

## Compatibility note

Scripts, cron jobs or documentation that call the removed mount command names must be updated explicitly. v3.7.0 does not provide compatibility wrapper files because doing so would keep the obsolete commands in the public-command inventory and undermine the one-purpose naming model introduced by this release.


## Real-host follow-up

The 2026-08-20 v3.7.0 full real-Proxmox run passed all six `30-mount.sh` cases plus the additional all-drive lifecycle case in `85-qol-workflows.sh`. Direct LVM read-only/read-write mounting, one-drive root-role detection, partitioned media through `kpartx`, all-drive ownership-state cleanup and dry-run immutability all completed without anomalies. v3.7.1 therefore does not change the consolidated mount engine.
