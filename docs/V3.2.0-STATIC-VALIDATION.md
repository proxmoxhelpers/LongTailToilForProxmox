## State semantics

For create-and-add commands:

```text
hot      source VM unchanged
pause    pause/resume running source VM
stop     stop source VM and leave it stopped
restart  stop source VM, then start it after success
```

For overwrite commands the same modes apply to the **destination VM**, because that VM is losing/replacing an existing disk.

An already-stopped VM is not started merely because `restart` was specified.

## Overwrite preservation contract

The new overwrite helpers do not destroy the displaced destination disk.

The intended transaction is:

```text
preflight
create + verify replacement
apply requested destination state
detach old destination disk
verify old disk became unusedN
attach replacement at exact original slot
restore requested destination state
verify replacement + preserved old disk
```

If replacement attachment fails before the new volume becomes referenced, the helper attempts to restore the exact original destination value. An unattached replacement volume is eligible for automatic cleanup only when no guest config references it.
