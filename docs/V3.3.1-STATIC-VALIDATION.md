# v3.3.1 Static Validation

Date: 2026-08-17

Version 3.3.1 adds project-wide support for both Proxmox managed-LV naming families:

```text
vm-VMID-disk-N
base-VMID-disk-N
```

The audit was semantic rather than a blind regex replacement. Existing helpers that operate on canonical paths, storage IDs, configured slots or LV UUIDs were already family-neutral and were left that way.

Local acceptance checks include:

```text
Project commands                    : 40
Standalone top-level helpers        : 40/40
POSIX /bin/sh syntax                : all project/test shell files
README wget+chmod coverage          : 40/40
Test-matrix command coverage        : 40/40
Plan-only test-group launchers      : all groups
Managed vm/base naming regression   : enabled
```

The static suite explicitly checks that the helpers with naming-sensitive behavior contain both `vm` and `base` handling.

Real integration fixtures were added for:

- template/base grouping and orphan detection;
- template VMID changes;
- base-family disk renumbering;
- base-family volume-name repair;
- base-volume recovery;
- numeric source selection from a template;
- template copy/snapshot add;
- template snapshot overwrite.

This record does **not** prove those newly added template/base paths against a real Proxmox host.
