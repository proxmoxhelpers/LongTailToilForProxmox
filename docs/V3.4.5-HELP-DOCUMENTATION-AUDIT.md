# v3.4.5 — Help and per-helper documentation audit

Date: 2026-08-17

Version 3.4.5 is a documentation/help hardening release built on the v3.4.4 behavior under real-host test.

## Public helper audit

All 42 top-level public helpers were executed with:

```sh
./helper.sh --help
```

The audit requires:

- exit status 0;
- a visible `Usage` section or line;
- no dependency on passing the real-operation elevation/preflight gate first.

The same scripts were also checked with `--version`.

## Per-helper documentation

Every public helper now has a matching page:

```text
docs/<helper-without-.sh>.md
```

Each page contains:

- the script purpose from the public helper inventory;
- a direct link back to the script and README;
- the callable `./helper.sh --help` command;
- the current built-in help output;
- the standalone GitHub `wget ... && chmod +x` install command;
- examples carried from the README helper section;
- safety/dry-run notes;
- version output.

The complete index is [`HELPERS.md`](HELPERS.md).

## README helper headings

Every helper heading now uses the same format:

```md
#### [`change-vmid-of-vm.sh`](../change-vmid-of-vm.sh) · [doc](change-vmid-of-vm.md)
```

In the actual repository README the relative targets are rooted from the repository top: the script link targets `change-vmid-of-vm.sh` and the documentation link targets `docs/change-vmid-of-vm.md`.

The script name therefore opens the standalone helper itself, while `doc` opens that helper's documentation page.

## Regression enforcement

The static suite now verifies for every top-level helper:

1. `--help` returns success;
2. help output contains `Usage`;
3. README contains exactly one linked script/doc heading;
4. the referenced documentation file exists;
5. the page title matches the helper;
6. the page contains the callable `./helper.sh --help` command;
7. README contains exactly one standalone install line;
8. the test matrix contains exactly one command row.

This prevents future helper additions or renames from silently leaving help or documentation behind.

## Behavior boundary

v3.4.5 does not intentionally change the v3.4.4 storage/mutation transaction semantics or the 86-case real integration definition. The real-host run that was already in progress against v3.4.4 remains the authoritative behavior signal for those transaction changes.
