# v3.4.2 — Full Test and Harness Safety Audit

Date: 2026-08-17

Version 3.4.2 is a test/harness and documentation hardening release. The public helper set remains 42 commands; the changes are concentrated in integration coverage, refusal-path verification, cleanup safety and documentation accuracy.

## What was audited

Every public helper was reviewed against its actual behavior rather than counted as "covered" merely because one integration case existed.

The audit checked:

- normal success paths;
- dry-run immutability;
- destructive confirmation;
- shared-volume/refusal paths;
- QEMU/LXC runtime-state transitions;
- source and destination selector variants;
- `vm-` and `base-` managed-volume families;
- overwrite archive/delete/empty-target transactions;
- boot-order updates;
- byte/content preservation for copy/move/import/export;
- partitioned and direct filesystem mounts;
- template and LXC VMID paths;
- QEMU and LXC network paths;
- cleanup ownership boundaries.

The resulting suite definition contains 84 real integration cases across 42 public helpers, plus the static/CLI safety contracts.

## Harness safety improvements

### Stronger dry-run/refusal snapshots

`run_dryrun_unchanged` and refusal assertions now compare more than configuration text. The test-owned snapshot includes:

- disposable LV metadata;
- sampled disposable LV content hashes;
- disposable QEMU configuration and runtime state;
- disposable LXC configuration and runtime state;
- disposable storage definitions;
- files and non-files below the test data directory;
- mounts below the test sandbox.

An accidental stop/suspend, content write, mount leak or storage-definition mutation now causes the before/after comparison to fail.

### Stronger protected-host baseline

The protected pre-existing baseline now includes:

- VG/PV/LV metadata;
- canonical Proxmox storage semantics;
- existing guest-configuration checksums;
- local QEMU runtime status;
- local LXC runtime status;
- firewall-file checksums.

This extends the earlier protection from "configuration unchanged" to "configuration and local runtime/firewall state unchanged".

### Fail-closed cleanup

Cleanup no longer treats a matching test guest name as sufficient proof that it is safe to purge.

Before a disposable QEMU VM or LXC CT can be destroyed, the harness requires:

1. exact expected test identity; and
2. every storage-backed reference still resolves only to storage/VGs owned by the current test run.

Cleanup is layered:

```text
unresolved test mounts
    -> stop deeper cleanup

remaining owned VM/CT
    -> do not remove test storage/VGs

remaining test storage definition
    -> do not remove test VGs/loops

remaining test VG/loop
    -> retain ownership records for manual recovery
```

A cleanup problem narrows what the harness is allowed to delete; it never broadens deletion.

Pre-existing project backup paths are recorded before tests begin and are never removed by cleanup.

### LXC and regular-LV fixtures

The harness now creates disposable config-only LXC fixtures for CT-specific VMID/network paths instead of leaving those behaviors untested.

A third loopback-owned regular VG is used for the regular-LV copy path. This lets the suite test the important rule that a regular LV receives full writes and must not use sparse-copy behavior intended for thin destinations.

## Coverage enforcement

The static suite now fails if:

- a public helper has no non-static integration reference;
- a mutating public helper has no `run_dryrun_unchanged` integration case;
- README helper headings do not match the 42 public scripts exactly;
- README standalone `wget ... && chmod +x` lines do not match the public scripts exactly;
- `tests/TEST-MATRIX.md` does not contain exactly one command row per public helper.

The matrix records representative success and negative/variant coverage. A row does not claim combinatorial coverage of every possible argument ordering, filesystem, storage backend or injected failure point.

## Validation boundary

The v3.4.2 suite definition and static contracts are locally validated, but the expanded 84-case integration set still requires a real disposable Proxmox run.

Run:

```sh
./tests/run-all-tests.sh --run --verbose
```

Promote v3.4.2 to an integration-validated baseline only if the run finishes with:

```text
failed cases                  : 0
protected-state anomalies     : 0
unexpected cleanup ownership  : 0
```

Until then, v3.4.2 is a release candidate with a stronger test definition, not a new real-host validation claim.
