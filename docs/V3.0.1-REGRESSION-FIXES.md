# v3.0.1 Regression Fixes

## Summary

v3.0.1 fixes the POSIX `set -e` control-flow regressions exposed by the first real Proxmox v3.0.0 integration run.

The v3.0.0 run proved that the majority of the rewrite was already interfacing correctly with real Proxmox/LVM tools:

```text
30/36 integration cases passed
6/10 groups passed completely
0 protected-state anomalies
```

The six failed cases reduce to one shell-control-flow class plus cascade failures from cleanup.

## Root cause

This pattern is dangerous under `set -e` when it becomes the final command of a function:

```sh
probe && die "unexpected state"
```

For a negative probe, status 1 is often the *desired* result. But the AND-list itself also returns 1. If the function returns that status, `set -e` treats the normal state as a fatal error.

v3.0.1 uses:

```sh
if probe; then
    die "unexpected state"
fi
return 0
```

for these validators.

## Corrected commands

```text
rename-lvm.sh
renumber-vm-disks.sh
recover-vm-from-volumes.sh
unmount-vm-drives.sh
clone-vm-config-only.sh
copy-lvm.sh
move-lvm.sh
delete-lvm.sh
set-vm-boot-disk.sh
```

The first four fix observed failures.

The remaining commands were hardened because the same short-circuit style existed in paths that either happened not to be terminal in the current control flow or were not triggered by the current fixtures.

## Mount cascade

No evidence indicates a mount implementation failure.

The real v3.0.0 logs showed successful:

```text
mount
filesystem access
Linux-root detection
unmount
empty part1 removal
```

`mount-vm-disk.sh` and `mount-vm-root.sh` failed only because their cleanup call to `unmount-vm-drives.sh` inherited the false nonzero return from post-unmount verification.

## New regression gate

The static suite now includes:

```text
No set -e unsafe short-circuit die guards
```

and rejects `&& die` in executable project/library shell source.
