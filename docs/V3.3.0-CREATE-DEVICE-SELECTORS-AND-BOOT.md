# v3.3.0 Create-Helper Device Selectors and `boot`

Version 3.3.0 extends all four create helpers:

```text
create-disk-copy-and-add-to-vm.sh
create-disk-snapshot-and-add-to-vm.sh
create-disk-copy-and-overwrite-disk-on-vm.sh
create-disk-snapshot-and-overwrite-disk-on-vm.sh
```

## Source selectors

A source may still be a full LVM path:

```sh
./create-disk-snapshot-and-add-to-vm.sh /dev/pve/vm-123-disk-0 456
```

When the source is a VMID, the second positional selector may be either a backing disk number or an exact configured QEMU disk slot:

```text
123 disk-0
123 sata0
123 ide2
123 scsi4
123 virtio0
```

Exact source slots must already exist. A bare source bus such as `sata` is intentionally not accepted because a source must resolve to exactly one existing disk.

CD-ROM/cloud media is not accepted as a source disk.

## Destination selectors

For VMID destinations, selectors have three forms.

Backing disk number:

```text
disk-3
```

This preserves the existing behavior: the result uses `vm-DESTVMID-disk-3`. Add helpers attach it to the first free SCSI slot. Overwrite helpers replace that disk if active or create it on the first free SCSI slot if absent.

Exact QEMU slot:

```text
sata0
ide2
scsi4
virtio0
```

Add helpers require the slot to be empty. Overwrite helpers replace the disk when the exact slot is occupied, or create a new disk there when the slot is empty.

Bare bus:

```text
sata
ide
scsi
virtio
```

A bare bus means the first available slot on that bus. Because this selects a free slot, overwrite helpers use their empty-target/add path rather than displacing another disk.

The supported ranges are:

```text
ide0..ide3
sata0..sata5
scsi0..scsi30
virtio0..virtio15
```

## Backing disk numbers with slot/bus destinations

When a slot/bus selector is used instead of `disk-N`, the helper chooses the next physically/configuration-free standard backing name:

```text
vm-DESTVMID-disk-N
```

The device position and backing disk number are independent concepts: for example, `sata0` can legitimately reference `vm-456-disk-7`.

## `boot`

The optional keyword:

```text
boot
```

may appear anywhere on the command line.

After the new disk is attached, the helper moves the actual destination slot to the front of the VM boot order while preserving the remaining explicit order.

Example:

```text
before: order=ide2;net0
new disk attached at: virtio0
after:  order=virtio0;ide2;net0
```

For overwrite mode `restart`, the new boot order is applied **before** the destination VM is started.

## Examples

```sh
./create-disk-copy-and-add-to-vm.sh 123 scsi0 456 sata fastvg boot dryrun
./create-disk-snapshot-and-add-to-vm.sh 123 sata0 456 virtio0 pause boot dryrun
./create-disk-copy-and-overwrite-disk-on-vm.sh 123 scsi0 456 sata0 delete restart boot dryrun
./create-disk-snapshot-and-overwrite-disk-on-vm.sh 123 disk-0 456 virtio boot dryrun
```

State keywords retain their existing semantics: add helpers apply `pause|stop|restart` to the source VM; overwrite helpers apply them to the destination VM.
