# v3.1.0 New Helpers

Version 3.1.0 adds two standalone helpers to Proxmox LongTail Toil.

## `list-all-vm-lvm.sh`

Displays LVM logical volumes referenced by Proxmox QEMU and LXC guest configurations, grouped beneath each VMID.

Example:

```sh
./list-all-vm-lvm.sh
```

Typical output shape:

```text
VM 100  (QEMU) web01
  SLOT       LVM_PATH                               SIZE         POOL             ORIGIN
  scsi0      /dev/pve/vm-100-disk-0               32.00g       data             -

VM 101  (LXC) app01
  SLOT       LVM_PATH                               SIZE         POOL             ORIGIN
  rootfs     /dev/pve/vm-101-disk-0               16.00g       data             -

Remaining LVM volumes
LVM_PATH                               SIZE         POOL             ORIGIN
/dev/pve/root                          96.00g       -                -
/dev/pve/swap                          8.00g        -                -
/dev/pve/vm-999-disk-0                32.00g       data             -
```

The remaining section is intentionally broad. It includes:

- normal host/system LVs;
- thin pools;
- orphaned VM-style LVs;
- any other visible LV not resolved from a guest configuration.

LVM UUIDs are used internally to correlate Proxmox storage references with LVs, so storage aliases and `/dev` aliases do not cause the same LV to be counted as different devices.

## `move-disk-to-vm.sh`

Moves an existing LVM-backed QEMU disk reference to another QEMU VM without copying, deleting, or renaming the LV.

### Full LV path form

```sh
./move-disk-to-vm.sh /dev/pve/vm-123-disk-0 456
```

### Source VM + backing disk number form

```sh
./move-disk-to-vm.sh 123 0 456
```

The numeric selector means the backing LVM name:

```text
vm-123-disk-0
```

An explicit source slot is also accepted:

```sh
./move-disk-to-vm.sh 123 scsi0 456
```

The destination receives the disk on its first free `scsiN` slot.

### Source VM state modes

The default is hot-swap:

```sh
./move-disk-to-vm.sh 123 0 456
```

No pause or stop check is imposed on the source VM.

Pause the source before removing the disk, then resume it:

```sh
./move-disk-to-vm.sh 123 0 456 pause
```

Stop the source before removing the disk and leave it stopped:

```sh
./move-disk-to-vm.sh 123 0 456 stop
```

Stop the source before removing the disk, then start it again after the move:

```sh
./move-disk-to-vm.sh 123 0 456 restart
```

`pause`, `stop`, `restart`, `dryrun`, and `--dryrun` may appear anywhere on the command line. Only one source-state mode may be selected.

A VM that was already stopped is never started automatically.

### Transfer safety

For an active source disk, the helper detaches the disk from the source before attaching it to the destination. It does not intentionally make the same writable LV active in two VMs at once.

The backing LV is preserved throughout the transaction.

If an active source disk is detached but destination attachment fails before the destination configuration is touched, the helper attempts to restore the exact original source slot/value.

The helper also:

- resolves ownership by LVM UUID;
- refuses multiple guest references;
- refuses source/destination VM locks;
- refuses source snapshot/config sections;
- refuses host-mounted LVs;
- rechecks the source slot and destination slot immediately before mutation;
- warns when the removed source slot appears in the source boot order;
- verifies the destination reference and source-reference removal;
- supports normal project-wide dry-run behavior.

The LV name is deliberately not changed. Moving:

```text
/dev/pve/vm-123-disk-0
```

to VM 456 leaves that LV name unchanged. Use `fix-vm-volume-names.sh` later if you explicitly want backing-volume names normalized to the destination VMID.

## Test coverage

The v3.1.0 test matrix expands to 38 commands.

`10-inspection.sh` verifies `list-all-vm-lvm.sh` against an attached test LV plus an intentionally orphaned LV.

`40-disk-lifecycle.sh` exercises `move-disk-to-vm.sh` using:

```text
full LV path + default hot mode
source VM + disk number + pause
source VM + disk number + stop
source VM + disk number + restart
```

Every mutating integration path is dry-run checked first. The complete real Proxmox suite remains the final acceptance gate:

```sh
./tests/run-all-tests.sh --run --verbose
```
